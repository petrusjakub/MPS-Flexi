# Non-linear premium calculator rewrite for MPS Flexi

The single-page product HTML has been rewritten to replace a linear per-unit-rate calculator with a discrete lookup-based calculator backed by absolute kontribusi values per UP level. The old `PREMI_DATA` stored a single rate per age/plan/masa-bayar combination and multiplied linearly; the new structure stores one kontribusi figure for each of 7-10 discrete UP levels, eliminating the incorrect linear assumption. A secondary "berdasar kontribusi" mode interpolates backwards from a target payment to an estimated UP. Syariah terminology has been standardized (Plan A/B use "Uang Santunan", "Kontribusi", "Peserta"; Plan C keeps "UP", "Premi", "Nasabah"), and a floating WhatsApp button is always visible.

**Watch for:** Floating-point noise in PREMI_DATA produces values like `4099999.9999999995` and `16100000.000000002` (~100 instances) that could surface as ugly numbers during interpolation arithmetic (confirmed). File size is 734 KB, exceeding the stated 300 KB acceptance criterion when the base64 image is excluded (confirmed, ~359 KB without image). Age interpolation uses linear ratio across large gaps (age 30 to 39, or 39 to 65) which may yield misleading estimates for ages in those ranges (likely).

## High-level view

Approximately 100 kontribusi values in PREMI_DATA carry floating-point noise (e.g., `4099999.9999999995` instead of `4100000`). The calculator rounds with `Math.round()` which papers over most cases, and the Tabel Premi rendering via `.toFixed(1)` also masks the issue. However, embedding imprecise values makes the data harder to audit and could compound during interpolation arithmetic.

The age gaps in the source data (ages 31-38 not present, jump from 30 to 39; ages 40-64 not present, jump from 39 to 65) mean interpolation spans decades of actuarial change in a single linear step. A 50-year-old gets a value interpolated 42% of the way from age 39 to 65, which likely underestimates the true premium since mortality rates rise exponentially in this range. The disclaimer text exists but gives the same confidence treatment to a 1-year gap as to a 26-year gap.

The "berdasar kontribusi" reverse mode linearly interpolates between UP levels to estimate coverage for a given budget. Since the relationship between UP and kontribusi is explicitly non-linear, this interpolation deviates from truth, though for adjacent levels the local error is small.

PREMI_DATA contains Plan A IDR data, but the Plan A tab states "Data kontribusi Plan A dalam JSON tersedia hanya untuk mata uang USD." If the IDR entries were synthesized from USD rates rather than sourced from official tables, they could confuse users or produce incorrect quotes.

## PREMI_DATA structure and data fidelity

The new data structure is `PREMI_DATA[plan][currency][gender][age][masaBayar][upLevel] = absoluteKontribusi`. For Plan B IDR pria age 30 with masa bayar 10:

```
"30":{"10":{"2000000000":5100000,"2500000000":6300000,...,"50000000000":126500000}}
```

Approximately 100 values carry floating-point artifacts: `4099999.9999999995` instead of `4100000`, `16100000.000000002` instead of `16100000`, `8300000.000000001` instead of `8300000`. These originate from the data extraction step (likely division artifacts from the source PDF). In the calculator's "Berdasar UP" mode, `Math.round(kontribusi)` neutralizes the issue. In the Tabel Premi tab, `(v/1000000).toFixed(1)` also produces correct display. However, embedding imprecise values makes the data harder to audit and could surface in edge cases during interpolation arithmetic where rounding compounds.

## Age interpolation across sparse data

The interpolation logic:

```javascript
var ratio = (age - lower) / (upper - lower);
ageData[mk][uk] = lData[mk][uk] + (uData[mk][uk] - lData[mk][uk]) * ratio;
```

For Plan A, the available ages are 18-30, 39, and 65-70. A user entering age 50 gets data interpolated between 39 and 65 with ratio `(50-39)/(65-39) = 0.42`. Actuarial mortality rates are exponential in this range, not linear, so the interpolated value likely underestimates the true premium significantly for middle-aged users and overestimates for users just above 39.

There is no visual cue that the interpolation is spanning a 26-year gap versus a 1-year gap. Both get the same confidence treatment and the same disclaimer text.

## "Berdasar kontribusi" reverse lookup

The reverse mode iterates over known UP levels, finds the two bracketing the target kontribusi, and linearly interpolates between the UP values:

```javascript
estimatedUP = parseFloat(foundLower.up) + (parseFloat(foundUpper.up) - parseFloat(foundLower.up)) * ratio2;
```

This linear interpolation between UP levels is less defensible than the age interpolation, because the relationship between UP and kontribusi is explicitly non-linear (that's the entire reason for the rewrite). For adjacent UP levels (e.g., 2.5B to 3B) the local error is small, but for wider jumps (e.g., 10B to 50B) the linear assumption breaks down substantially.

## File size

The HTML file is 734 KB. The base64-encoded commission image accounts for roughly 375 KB, leaving ~359 KB for structure + data + scripts. The acceptance criterion stated "under 300KB (excluding the commission image base64)", so the file exceeds the target by ~60 KB. This is primarily due to the expanded PREMI_DATA structure storing absolute values for every UP level rather than a single rate per age.

## Komisi tab authentication

The password check is purely client-side: three hardcoded passwords (`mps123`, `flexi`, `manulife`) in plaintext JavaScript. Any user can view source or use browser developer tools to bypass it. This should not be relied upon for protecting sensitive commission information.
